# 🛠️ Vivado ILA Debug Pipeline & Methodology

מסמך זה מתאר את מתודולוגיית הדיבוג (Debug Pipeline) לאימות חומרה על גבי שבב ה-FPGA. המטרה היא מעבר משיטת "ניסוי וטעייה" (הדורשת זמן קומפילציה ארוך ומיותר) לתהליך עבודה דטרמיניסטי, מבוסס Checkpoints, המוודא את שלמות האותות בכל שלב בדרך לסיליקון.

---

## ⏱️ מתי באמת צריך להריץ סינתזה (Synthesis)?
תהליך הסינתזה מתרגם את קוד ה-RTL (VHDL) לרשת שערים לוגיים (Netlist). זהו תהליך "יקר" בזמן, ויש להריצו מחדש **אך ורק** בתרחישים הבאים:

1. **שינוי בלוגיקה:** עריכת קובצי המקור (`.vhd` / `.v`) ושינוי פונקציונליות או אלגוריתמיקה.
2. **עדכון IP Cores:** שינוי הגדרות של רכיבי חומרה בנויים (כגון שינוי תדר ב-Clock Wizard, או שינוי עומק זיכרון ב-BRAM).
3. **הוספת תגיות דיבוג בקוד:** הוספת שורת התגית `(* mark_debug = "true" *)` ישירות בתוך קוד ה-VHDL.

**מתי לא צריך סינתזה? (מעבר ישיר ל-Implementation):**
* שינויים בקובץ האילוצים (`.xdc`) – כגון שינוי מיפוי פינים (Pinout).
* סימון אותות לדיבוג דרך ממשק ה-Netlist ב-Vivado (קליק ימני -> `Mark Debug`).
* הרצת אשף ה-`Set Up Debug`.
* *במקרים אלו, הלוגיקה כבר מסונתזת, ונדרש רק שלב ההשמה והניתוב (Implementation) כדי לעדכן את החומרה.*

## 🚦 נוהל אימות תהליך הדיבוג (The 4-Step Pipeline)
אין להתקדם לשלב הבא ללא מעבר מבחן הקבלה (Pass) של השלב הנוכחי.
